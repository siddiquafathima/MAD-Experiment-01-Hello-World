# MAD Experiment 12: Access Web Services Using HTTP Request

A Mobile Application Development lab experiment demonstrating asynchronous web service consumption using HTTP/HTTPS requests, Kotlin Coroutines, `Dispatchers.IO`, `HttpURLConnection`-based networking, and JSON parsing in Android.

---

## 1. Aim

To develop an Android application that sends an HTTP GET request to a RESTful web service, retrieves JSON data, parses the response, and displays the user details on the screen using Kotlin Coroutines.

## 2. Concept & Technology Overview

- **RESTful Web Services:** Allow applications to exchange data using HTTP methods such as GET.
- **HTTP GET Request:** Retrieves information from a remote server.
- **Kotlin Coroutines:** Perform network operations asynchronously without blocking the main UI thread.
- **Dispatchers.IO:** Executes network and other input/output operations on a background thread.
- **Dispatchers.Main:** Updates the user interface safely on the main thread.
- **JSON Parsing:** Uses `JSONObject` to extract fields from the JSON response.
- **Error Handling:** Catches network and parsing errors to prevent the application from crashing.

### Scenario

The application fetches user details from a remote REST API and displays the user's name, email address, and city.

**API endpoint:** [JSONPlaceholder – User 1](https://jsonplaceholder.typicode.com/users/1)

## 3. Technologies Used

- **Language:** Kotlin
- **IDE:** Android Studio
- **Networking:** Java `URL` API
- **Asynchronous Processing:** Kotlin Coroutines
- **Data Format:** JSON
- **API:** JSONPlaceholder
- **UI:** Android XML Layouts

### 5.2 `MainActivity.kt`

This activity fetches remote user information on a background thread and updates the UI on the main thread.

```kotlin
package com.example.webservicehttpapp

import android.os.Bundle
import android.widget.Button
import android.widget.TextView
import androidx.appcompat.app.AppCompatActivity
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.launch
import kotlinx.coroutines.withContext
import org.json.JSONObject
import java.net.URL

class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        val btnFetch = findViewById<Button>(R.id.btnFetch)
        val tvResult = findViewById<TextView>(R.id.tvResult)

        btnFetch.setOnClickListener {
            CoroutineScope(Dispatchers.IO).launch {
                try {
                    val rawJson = URL(
                        "https://jsonplaceholder.typicode.com/users/1"
                    ).readText()

                    val json = JSONObject(rawJson)
                    val address = json.getJSONObject("address")

                    val result = """
                        Name: ${json.getString("name")}
                        Email: ${json.getString("email")}
                        City: ${address.getString("city")}
                    """.trimIndent()

                    withContext(Dispatchers.Main) {
                        tvResult.text = result
                    }
                } catch (e: Exception) {
                    withContext(Dispatchers.Main) {
                        tvResult.text = "Error: ${e.message}"
                    }
                }
            }
        }
    }
}
```

### 5.3 Required Dependencies

Ensure that Kotlin Coroutines are included in the app-level `build.gradle.kts` file.

```kotlin
dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.10.2")
}
```

If your project already uses a compatible Coroutines version, retain that version instead of adding a duplicate dependency.

**Important:** The sample uses `URL.readText()` on `Dispatchers.IO`, so the network request runs off the main thread. For a production application, prefer a lifecycle-aware scope such as `lifecycleScope` and configure connection/read timeouts.
